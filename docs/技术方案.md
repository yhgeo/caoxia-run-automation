## 〇、摘要：三个决定性发现

1. **苍霞乐跑是微信小程序**，不是独立 App → 沙盒隔离方案不可行，界面必须走点击/OCR
2. **FakeLoc 是自编译的 Xposed 模块，源码在手** → `startRoute()` 只有三个动作，全部可从外部触发，**"打开路线模拟"不需要点 UI**
3. **FakeLoc 自带里程达标通知**（`route_notify_km`）→ **里程监控不需要 OCR**，监听通知即可

结果：5 个环节中只剩「乐跑点开始」「乐跑点结束」需要 UI 自动化。

### 4.1 架构

### 4.2 配置存储：`/data/data/com.mo.fakeloc/shared_prefs/fakeloc.xml`

| Key | 含义 | 默认 |
| --- | --- | --- |
| `config_json` | `LocConfig` 的 JSON（含 `enabled`、经纬度、反检测开关） | — |

### 4.3 反检测相关字段（`LocConfig`，默认已开）

```kotlin
var jitterEnabled: Boolean = true     // 自然抖动
var jitterMeters: Double = 2.0

var satelliteCount: Int = 24          // 伪造卫星数

```

### 4.4 服务启动协议

```kotlin
const val ACTION_START   = "com.mo.fakeloc.action.START"    // 开始（里程清零）
const val ACTION_STOP    = "com.mo.fakeloc.action.STOP"
const val ACTION_REFRESH = "com.mo.fakeloc.action.REFRESH"  // 刷新（保持里程）
```

**不需要任何 extra** —— 配置全部从 `ConfigStore` 读。

`onStartCommand` 分支：
```kotlin
ACTION_STOP            -> stopEverything()
ACTION_START           -> startEverything(resetDistance = true)
ACTION_REFRESH, null   -> startEverything(resetDistance = false)
```

⚠️ `startEverything()` 里第一件事是 `if (!cfg.enabled) { stopEverything(); return }` —— **总开关必须先为 true**。

### 4.5 ★ `startRoute()` 的完整动作（`ui/AppState.kt:209`）

```kotlin
fun startRoute() {
    ConfigStore.saveRouteRunning(ctx, true)      // 1. route_running = true
    routeRunning = true
    persist(cfg.copy(enabled = true))            // 2. enabled = true
    FakeLocationService.start(ctx)               // 3. ACTION_START
}
```

**这就是"打开路线模拟"的全部。三步都是纯数据写入 + 一次服务启动，没有任何 UI 依赖。**

### 4.6 ★ 里程达标通知（`checkTargetDistance()`）

```kotlin
private fun checkTargetDistance() {
    val notifyKm = ConfigStore.routeNotifyKm(this)
    if (notifyKm <= 0.0 || targetNotified) return
    if (travelledMeters < notifyKm * 1000.0) return
    targetNotified = true
    // 发一条 IMPORTANCE_HIGH 通知：标题「已完成 2.50 km」，会响会震
}
```

`travelledMeters` 每 tick 累加：`travelledMeters += speedMs * (TICK_MS / 1000.0)`，即**配速 × 时间**。

**这条通知是天然的里程信号源** —— AutoX.js 用 `events.observeNotification()` 监听即可，完全绕开 OCR。

## 五、★ 改造方案

### 5.1 目标：把"打开路线模拟"变成一条命令

**推荐做法：改源码，让 `ACTION_START` 自动开启路线。**

改动极小（`service/FakeLocationService.kt`）：

```kotlin
// 原
ACTION_START -> startEverything(resetDistance = true)

// 改为
ACTION_START -> {
    // 自动化入口：外部拉起时自动打开总开关 + 路线开关
    ConfigStore.saveRouteRunning(this, true)
    ConfigStore.save(this, ConfigStore.load(this).copy(enabled = true))
    startEverything(resetDistance = true)
}
```

改完后，一条命令即可启动完整路线模拟：

```bash
# 启动（需 root，因 service exported=false）
su -c "am start-foreground-service -n com.mo.fakeloc/.service.FakeLocationService \
       -a com.mo.fakeloc.action.START"

# 停止（注意源码里 stop 用的是 startService，非 foreground）
su -c "am startservice -n com.mo.fakeloc/.service.FakeLocationService \
       -a com.mo.fakeloc.action.STOP"
```

### 5.2 可选增强：加一个广播入口（免 root）

若不想依赖 root 授权，可新增一个 exported 的 `AutomationReceiver`：

```kotlin
class AutomationReceiver : BroadcastReceiver() {
    override fun onReceive(ctx: Context, intent: Intent) {
        when (intent.action) {
            "com.mo.fakeloc.automation.START_ROUTE" -> {
                ConfigStore.saveRouteRunning(ctx, true)
                ConfigStore.save(ctx, ConfigStore.load(ctx).copy(enabled = true))
                FakeLocationService.start(ctx)
            }
            "com.mo.fakeloc.automation.STOP_ROUTE" -> {
                ConfigStore.saveRouteRunning(ctx, false)
                FakeLocationService.stop(ctx)
            }
        }
    }
}
```

Manifest 注册（带签名级权限，避免被其他 App 滥用）：

```xml
<permission android:name="com.mo.fakeloc.permission.AUTOMATION"
            android:protectionLevel="signature" />
<receiver android:name=".AutomationReceiver"
          android:exported="true"
          android:permission="com.mo.fakeloc.permission.AUTOMATION">
    <intent-filter>
        <action android:name="com.mo.fakeloc.automation.START_ROUTE" />
        <action android:name="com.mo.fakeloc.automation.STOP_ROUTE" />
    </intent-filter>
</receiver>
```

⚠️ `signature` 级权限要求调用方同签名 —— 若由 AutoX.js 调用会失败。二选一：
- 改为 `normal` 权限（谁都能发，但只能触发启停，风险可控）
- 或干脆不加权限，靠 action 名保密

### 5.3 不改源码的过渡方案

若暂不改源码，可用 root 直接改 prefs：

```bash
# 1. 杀掉进程，释放 prefs 内存态
su -c "am force-stop com.mo.fakeloc"
# 2. 改 XML：route_running=true，并把 config_json 里的 enabled 改为 true
#    （需要 sed / python 处理，注意 XML 转义）
# 3. 启动服务
su -c "am start-foreground-service -n com.mo.fakeloc/.service.FakeLocationService \
       -a com.mo.fakeloc.action.START"
```

缺点：每次都要改文件，且 `config_json` 是嵌套 JSON 字符串，处理麻烦。**不如直接改源码。**

### 里程口径注意

FakeLoc 的 `travelledMeters` 是**配速 × 时间**（匀速理论值）；乐跑是按 **GPS 轨迹采样**累加。两者方向一致但有偏差。

建议：`route_notify_km` 先设 **2.5 km**，跑一次观察乐跑实际显示多少，再校准阈值（可能要设到 2.6–2.7 才够）。

### 9.5 附：git 环境踩坑（本项目目录特有）

该源码目录所在的文件系统**会拦截 git 的原子 ref 写入**（「子目录内建文件 + rename」组合操作），表现为：

- `git checkout -b <带斜杠分支>` → `.git` 被整体清空
- `git commit` → commit 对象已生成，但 ref 未写入，`git log` 报 "does not have any commits yet"
- `git update-ref` → **exit=0 假成功**，文件实际不存在

绕过流程（已验证）：

```bash
# 1. 用 commit-tree 直接构造带 parent 的 commit（只写 objects，不碰 refs）
NEW_SHA=$(git commit-tree <tree> -p <parent> -F .git/COMMIT_EDITMSG)
# 2. 手动写分支 ref
mkdir -p .git/refs/heads/feat && printf '%s\n' "$NEW_SHA" > .git/refs/heads/feat/<branch>
# 3. 手动补 remote-tracking ref
mkdir -p .git/refs/remotes/origin/feat && printf '%s\n' "$NEW_SHA" > .git/refs/remotes/origin/feat/<branch>
# 4. 推送（gh 作临时 credential helper，代理走 7897）
git -c credential.helper= -c credential.helper='!gh auth git-credential' \
    -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 \
    push origin HEAD:refs/heads/<branch>
```

### 10.2 脚本

`scripts/caoxia-run.js` —— 完整链路：

```
广播启动 FakeLoc 路线 → 回桌面点快捷方式 → 点「开始跑步」
→ 监听达标通知 → 点「结束」→ 广播停止 FakeLoc
```

设计要点：
- **免 root**：全程走 `AutomationReceiver` 广播（AutoX.js 的 `shell()` 权限同 App 进程，普通模式执行不了 `am`）
- **按钮定位双策略**：优先文字查找，回退坐标（WebView 常读不到文字，两条路都要留）
- **异常自动回滚**：任何环节崩溃都广播 STOP，不让虚拟定位后台空跑
- `dryRun` 开关可空跑验证流程

**状态**：✅ 已推送至 `/sdcard/脚本/caoxia-run.js`

### 10.3 ★ 部署阻塞：realmeUI 收紧了 adb shell 权限

| 尝试 | 结果 |
| --- | --- |
| `settings put secure ...` | ❌ 缺 `WRITE_SECURE_SETTINGS` |
| `pm grant <pkg> <perm>` | ❌ 缺 `GRANT_RUNTIME_PERMISSIONS` |
| `su -c ...` | ❌ `Permission denied`（Magisk 未授权 shell） |

**结论：开无障碍、授运行时权限这类操作，在这台机器上只能手动做。**
仍可用：`pm install` / `adb push` / `am broadcast` / `query-receivers` / 各类只读 `dumpsys`。

### 10.4 ★ 另一阻塞：LSPosed 要求重启

触发前基线检查时捕获到 LSPosed 系统通知：

```
pkg=android id=2001 tag=com.mo.fakeloc
text = "com.mo.fakeloc 已更新，由于作用域包含系统框架，需重启以应用更改"
```

这条通知同时确认了两件好事 —— **FakeLoc 模块确实已启用**、**作用域包含系统框架**（虚拟定位 hook `LocationManager` 所必需）。
但新装的 APK **必须重启手机**才能让 LSPosed 重新注入（system_server 无法热重载）。

3. **重启手机**（让 LSPosed 加载新 FakeLoc）

### 11.3 ★ ColorOS 拦截 App 后台启动（方案硬伤，必须解决）

首次广播后服务没起来、**进程反而消失**。logcat 根因：

```
W OplusAppStartupManager: prevent start com.mo.fakeloc,
  cmp ComponentInfo{com.mo.fakeloc/com.mo.fakeloc.data.ConfigProvider}
  by contentprovider com.android.providers.settings callingUid 1000, scenePriority = 0
```

广播确实送达（`dumpsys activity broadcasts` 有 `BroadcastRecord`），但系统不让进程起来。

- **临时绕过**：先用 `monkey -p com.mo.fakeloc -c android.intent.category.LAUNCHER 1` 拉起界面，再发广播
- **根本解法**：把 FakeLoc 加入 **ColorOS 自启动白名单**（设置 → 应用管理 → 自启动）
- `am start-foreground-service` 不可行：Service 是 `exported=false`，报 `Requires permission not exported from uid`

### 11.4 ★ 里程口径最终结论

| 时点 | FakeLoc | 乐跑显示 | 偏差 |
| --- | --- | --- | --- |
| 2:49 | 0.53 km | 0.57 km | +7.5% |
| 达标 | **2.00 km** | **2.02 km** | **+1%** |
